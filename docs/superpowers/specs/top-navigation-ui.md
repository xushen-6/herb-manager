# 本草平台顶部导航界面改造设计

## 当前问题

当前 MainFrame 使用固定宽度的左侧深绿色侧栏承载品牌、业务菜单和退出操作，内容区同时承担顶部信息栏和页面内容。该布局在窗口变窄时可用空间不足，页面切换缺少连续反馈，统计卡片、表格和操作按钮的公共视觉规则也不够集中。

本次改造只调整 Swing View 层的布局和视觉，不重写业务服务、数据库访问或权限校验。

## 目标视觉

延续中药材主题的深绿色、米白、浅灰和金色点缀，参考清爽的资源工作台：

- 64～76px 的白色顶部导航，左侧为“本草”品牌，中间为业务菜单，右侧为当前用户、角色和退出操作。
- 页面内容放在浅灰背景上，以白色卡片、轻边框、圆角和低对比阴影组织信息。
- 页面标题、说明文字、统计数字形成清晰层次；内容区使用最大宽度约 1280px 的居中留白，窄窗口仍可滚动。
- 当前导航使用绿色文字、浅绿色背景和底部高亮线；按钮统一提供 hover、pressed、focus 和 disabled 状态。

## 顶部导航结构

`MainFrame` 使用 `BorderLayout`：

1. `NORTH`：`TopBar`，包含品牌区、菜单区和用户区。
2. `CENTER`：可滚动的页面容器，内部使用 `CardLayout` 或当前页面替换机制承载工作台、药材管理、库存流水、问答、用户管理、登录日志和个人资料。
3. `SOUTH`：轻量状态条，显示数据库模式和计量单位。

菜单来源继续复用现有 `navigation` 映射。角色可见性保持原规则：管理员显示用户管理和登录日志，管理员/药师显示库存流水，所有角色显示工作台、药材管理、智能问答和个人资料。窄窗口时可见菜单保留核心入口，其余入口收纳到“更多菜单”弹出菜单，弹出项仍触发现有导航按钮动作。

## 响应式规则

- **宽度 >= 1200**：顶部导航完整展开；菜单横向显示品牌、主要业务入口和用户区；首页统计卡片为四列；内容最大宽度约 1280px，左右保留自然留白。
- **宽度 900～1199**：顶部导航压缩内边距和菜单间距，用户区保留头像/姓名/退出；统计卡片切换为两列；页面内容和表格由滚动容器承载。
- **宽度 < 900**：菜单按钮折叠为“更多菜单”，品牌区仅保留紧凑标识，用户区减少文字但保留角色和退出；统计卡片为单列；所有页面进入垂直滚动，禁止用绝对坐标遮挡内容。

组件宽度通过 `BorderLayout`、`GridBagLayout`、`GridLayout`、`BoxLayout` 和 `CardLayout` 分配，窗口 `ComponentListener` 触发导航和卡片布局刷新。图片只使用等比例缩放。

## 动效规则

- 页面切换使用 `javax.swing.Timer`，在约 180～220ms 内完成轻微向上位移和淡入感；动画只更新轻量 View 状态，不启动额外线程。
- 顶部导航和按钮使用鼠标进入/退出/按下状态改变前景色、背景色或边框；禁用状态降低对比度并交给现有 `Tasks.run` 控制。
- 数据库操作继续通过 `Tasks.run` 离开 EDT，回调在 EDT 更新组件；不新增阻塞式数据库调用。

## 不改动的业务功能

- 不改变 `Platform` 的任何业务接口、数据库逻辑、事务边界和权限判断。
- 保留登录/注册、邮箱验证码、角色菜单、药材档案、库存入出库、库存流水、问答、用户管理、登录日志、个人资料和密码修改。
- 保留现有演示账号和 MySQL/H2 双数据库支持。
- 保留现有组件名称、异步任务、查询竞态保护和退出登录返回 `LoginFrame` 的行为。
- 不读取、不输出、不提交 `config.properties` 中的敏感信息，不覆盖已有用户修改。
